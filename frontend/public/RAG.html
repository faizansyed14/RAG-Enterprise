Enterprise RAG · Business to Technical Walkthrough

From business problem to trusted document answers

1

Business problem

Teams have many files and formats, but finding reliable information quickly is difficult.

Problem 01
Information is scattered
Important answers may be buried in PDFs, spreadsheets, emails, schedules and scanned documents.
Problem 02
Manual search is slow
Users spend time opening files, scanning pages and checking whether an answer is actually supported.
Problem 03
AI answers must be trusted
The assistant must answer from approved documents and show exactly where the answer came from.
Business need: ask a natural-language question across company documents and get a fast, traceable answer linked to the source page.

4

How the application works

There are only two major phases to explain.

Phase A
Prepare the documents
Upload → validate → store original → normalize → extract → build one document tree → summarize → save page text → indexed.
Phase B
Answer questions
User asks → agent finds the document → reads its structure → opens the relevant pages → answers from evidence → returns citations.
Key design point: every uploaded document creates its own independent tree. There is no single cross-document knowledge graph.

Normal files

Scanned PDF
Vision OCR reads each page. OCR text continues into the tree pipeline; visual-page embeddings are stored in Qdrant.

A leaf is the lowest structural section. It does NOT mean the full text is stored only in this summary. The real text is still stored in pages.json.
↓
ACTUAL PAGE EVIDENCEpages.json · page 5
Full extracted page text example:

“The survey was conducted between March and June. A total of 482 participants responded. Participants were divided into three groups based on department and experience level. Responses were collected through an online questionnaire and verified before analysis.”

What this level means:
This is the real source content the agent reads before answering.
Parent node = broad section
Methodology
Tells the agent: “The information about how the study was performed is somewhere in pages 4–8.”
Child / leaf = narrower topic
Data Collection → Survey Participants
Helps the agent narrow from a broad section to the most relevant subsection and page.
pages.json = source evidence
482 participants
The exact detailed facts are read from the page text, not assumed from the summary.
tree.json — parent example
{
  "title": "Methodology",
  "node_id": "node-002",
  "start_index": 4,
  "end_index": 8,
  "summary": "Explains how the research was designed, how participants were selected, how data was collected, and how responses were analyzed."
}
tree.json — child example
{
  "title": "Data Collection",
  "node_id": "node-002-001",
  "start_index": 4,
  "end_index": 5,
  "summary": "Describes the survey process, participant selection and collection period."
}
pages.json — actual evidence
{
  "page_number": 5,
  "markdown": "The survey was conducted between March and June. A total of 482 participants responded..."
}
The easiest way to explain this: Parent nodes tell the AI the broad area, child nodes narrow the topic, leaf nodes identify the lowest useful section, and pages.json contains the complete source text used for the final answer.

How the tree is created

The LLM does not invent the entire hierarchy.

01
Layout extraction

Text positions, fonts, headings, bookmarks and page boundaries.

→
02
Initial tree

Mostly deterministic parent / child / leaf boundaries.

→
03
Optimize

Merge unhelpful nodes and simplify structure.

→
04
Optional LLM expansion

Long sections may be inspected for real subsections.

→
05
Summaries

Leaves first, then parents, bottom-up.

Why this matters: summaries help navigation, but the original page content remains the factual evidence source.

10

Important boundaries

Keep these points clear when explaining the architecture.

  • No vector search over normal document text.
  • No cross-document knowledge graph.
  • No fixed number of sections or nodes.
  • No open-ended indexing loop.
  • Summaries are navigation aids, not source-of-truth facts.
  • Full page content remains in pages.json.
  • Qdrant is for scanned / visual-page retrieval only.
  • Answers are grounded after reading actual document content.
